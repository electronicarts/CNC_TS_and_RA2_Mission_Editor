# FinalAlert 2 MCP

Этот билд FinalAlert 2 запускает локальный Streamable HTTP MCP-сервер внутри редактора. Через него MCP-клиент может читать состояние карты, создавать и открывать карты, менять рельеф и высоты, расставлять ресурсы, точки старта и объекты, проверять результат, получать превью и сохранять карту.

Сервер работает только пока открыт редактор. Команды, затрагивающие карту, выполняются в UI-потоке FinalAlert 2; перед автоматизацией закройте модальные окна редактора.

Это самостоятельная сборка открытых исходников FinalAlert 2 версии 2.x. Не запускайте её через Syringe и не подключайте к ней `FA2sp.dll`: FA2sp рассчитан на адреса оригинального закрытого бинарника FinalAlert 2 1.02. Для работы нужны законно установленная Red Alert 2 / Yuri's Revenge с игровыми MIX-файлами и x86-компоненты [Microsoft Visual C++ Redistributable 2015–2022](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist) (`mfc140.dll`, `msvcp140.dll`, `vcruntime140.dll`).

## Быстрый запуск

По умолчанию используются адреса:

- MCP endpoint: `http://127.0.0.1:7462/mcp`
- проверка процесса: `http://127.0.0.1:7462/health`
- конфигурация: `FinalAlertMCP.ini` рядом с EXE редактора

Запустите редактор, затем из каталога билда выполните безопасный smoke test. Он вызывает только чтение и служебные методы, карту не изменяет:

```powershell
.\Test-FinalAlertMcp.ps1
```

Если в `FinalAlertMCP.ini` указан `AuthToken`, передайте его параметром или через переменную окружения:

```powershell
.\Test-FinalAlertMcp.ps1 -Token 'ваш-секрет'

$env:FINALALERT_MCP_TOKEN = 'ваш-секрет'
.\Test-FinalAlertMcp.ps1
Remove-Item Env:FINALALERT_MCP_TOKEN
```

Скрипт проверяет `/health`, полный legacy-сеанс (`initialize`, `notifications/initialized`, `tools/list`, `finalalert.get_status`, `DELETE`) и современный stateless-путь (`server/discover`, `tools/list`, `finalalert.get_status`).

## Конфигурация

Секция `[Server]` файла `FinalAlertMCP.ini` содержит:

| Ключ | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `Enabled` | `1` | `0` полностью отключает сервер. |
| `BindAddress` | `127.0.0.1` | Адрес прослушивания. Оставляйте loopback. |
| `Port` | `7462` | Локальный TCP-порт. |
| `Endpoint` | `/mcp` | Единый MCP endpoint. |
| `AuthToken` | пусто | Необязательный Bearer token для всех запросов, включая `/health`. |
| `AllowedHosts` | `localhost,127.0.0.1,[::1]` | Разрешённые значения HTTP `Host`. |
| `AllowedOrigins` | `https://chatgpt.com,https://chat.openai.com` | Разрешённые внешние HTTP `Origin`; локальные origin этого порта также принимаются. |
| `MaxRequestBytes` | `16777216` | Максимальный размер запроса, 16 MiB. |

Настройки доступны в меню **Options → MCP settings...** (в русском интерфейсе **Параметры → Настройки MCP...**). В окне можно включить или отключить сервер при запуске, изменить порт и путь подключения, токен авторизации, разрешённые хосты и источники, а также максимальный размер запроса (от 1024 до 67108864 байт). Адрес прослушивания закреплён за `127.0.0.1`. Окно показывает текущее состояние сервера и URL для подключения после перезапуска.

Кнопка **OK** сохраняет настройки в `FinalAlertMCP.ini` рядом с редактором. **Отмена** не сохраняет изменения. Изменения применяются после перезапуска редактора. При изменении порта, пути или токена обновите соответствующие настройки MCP-клиента.

## Два поколения MCP на одном endpoint

Сервер намеренно поддерживает старых и новых клиентов на одном `/mcp`.

### Legacy MCP 2025-11-25

Клиент отправляет `initialize`, получает `MCP-Session-Id`, отправляет `notifications/initialized` и повторяет заголовок сеанса в последующих запросах. Сеанс закрывается `DELETE /mcp` с `MCP-Session-Id`. Также принимаются совместимые legacy-версии `2025-06-18` и `2025-03-26`.

### MCP 2026-07-28

Современный протокол stateless: `initialize`, `MCP-Session-Id`, отдельный GET-поток и `DELETE` ему не нужны. Каждый `POST` сам описывает запрос:

- `MCP-Protocol-Version: 2026-07-28`;
- `Mcp-Method` точно совпадает с JSON-RPC `method`;
- для `tools/call` заголовок `Mcp-Name` точно совпадает с `params.name`;
- `params._meta` содержит `io.modelcontextprotocol/protocolVersion`, сведения о клиенте и его capabilities.

Для обнаружения возможностей используется `server/discover`. Обычный современный результат содержит `resultType: "complete"`; `tools/list` дополнительно возвращает подсказки для кеширования. `GET /mcp` не используется и отвечает `405`.

Минимальный современный вызов статуса:

```http
POST /mcp HTTP/1.1
Host: 127.0.0.1:7462
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: finalalert.get_status

{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"finalalert.get_status","arguments":{},"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientInfo":{"name":"example","version":"1.0"},"io.modelcontextprotocol/clientCapabilities":{}}}}
```

## Подключение ChatGPT через Secure MCP Tunnel

Облачный ChatGPT не может обращаться к `127.0.0.1` вашего компьютера напрямую. Не меняйте `BindAddress` на `0.0.0.0` и не пробрасывайте порт 7462 в Интернет. Для частного сервера используйте [официальный Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels): `tunnel-client` запускается на том же компьютере, делает исходящее HTTPS-соединение с OpenAI и пересылает запросы в локальный endpoint без входящего публичного порта.

Общий порядок:

1. Создайте `tunnel_id` в настройках туннелей OpenAI Platform и свяжите его с нужной Platform organization и ChatGPT workspace.
2. Установите актуальный `tunnel-client` и выполните `tunnel-client help quickstart` — точный набор параметров зависит от версии клиента.
3. Создайте профиль с локальным адресом `http://127.0.0.1:7462/mcp`, например:

   ```powershell
   $env:CONTROL_PLANE_API_KEY = 'ключ-для-tunnel-client'

   tunnel-client init `
     --profile finalalert-local `
     --tunnel-id tunnel_0123456789abcdef0123456789abcdef `
     --mcp-server-url http://127.0.0.1:7462/mcp

   tunnel-client doctor --profile finalalert-local --explain
   tunnel-client run --profile finalalert-local
   ```

4. В ChatGPT откройте Plugins, создайте developer-mode app, выберите тип подключения **Tunnel** и укажите этот `tunnel_id`.
5. Оставляйте редактор и `tunnel-client run` запущенными во время работы.

Secure MCP Tunnel предназначен для частного подключения и developer-mode тестирования. Для публикации общедоступного plugin нужен стабильный публичный HTTPS MCP endpoint. Если включён локальный `AuthToken`, настройте профиль используемой версии `tunnel-client` на отправку того же `Authorization: Bearer ...`; не помещайте секрет в README, логи или репозиторий.

## Безопасность и сохранность карт

- Оставляйте сервер на `127.0.0.1`; для удалённого доступа используйте туннель или контролируемый HTTPS proxy.
- Установите длинный случайный `AuthToken`, если к локальному порту могут обращаться недоверенные процессы. Тест-клиент токен не печатает.
- Не расширяйте `AllowedHosts` и `AllowedOrigins` до `*`. Эти проверки защищают локальный редактор от DNS rebinding и запросов с посторонних веб-страниц.
- Для каждой изменяющей команды обязателен непустой уникальный `operationId` (рекомендуется UUID). При сетевом повторе ровно той же операции повторно используйте тот же ID; сервер вернёт закешированный результат вместо второй мутации.
- Перед большими изменениями откройте или создайте карту, прочитайте её состояние, а первый результат сохраняйте в новый файл. Не перезаписывайте единственную копию карты до визуальной проверки.
- Низкоуровневые `finalalert.set_ini_value` и пакетный `finalalert.apply_map_plan` используйте только после проверки схемы из `tools/list`.
- Ошибка/тайм-аут клиента не всегда доказывает, что редактор не успел изменить карту. После тайм-аута проверьте статус и состояние, затем повторите запрос с тем же `operationId`.

## Semantic image: управляющая картинка для карты

`finalalert.import_semantic_image` создаёт новую карту и принимает BMP, PNG или JPEG: нужно передать ровно один источник — файл по абсолютному `imagePath` либо строку `imageBase64`/data URL. Это не прямой импорт красивого изображения в тайлы. Картинка является классифицированной маской: каждый пиксель описывает тип местности или специальную точку, затем координаты масштабируются на игровую ромбовидную сетку.

Для предсказуемого результата просите генератор изображения выдавать плоские области без теней, сглаживания, текста и JPEG-артефактов. Лучше сохранить PNG или BMP и использовать точные эталонные цвета:

| Смысл | Эталонный RGB | HEX | Что распознаётся |
| --- | --- | --- | --- |
| Обычная земля (`clear`) | `0, 0, 0` | `#000000` | Любой цвет, не попавший в остальные классы. |
| Трава (`green`) | `0, 200, 0` | `#00C800` | Зелёный доминирует минимум на 16; `G >= 125`. |
| Грубая земля (`rough`) | `0, 64, 0` | `#004000` | Зелёный доминирует минимум на 16; `G < 125`. |
| Песок (`sand`) | `230, 200, 80` | `#E6C850` | `R > 150`, `G > 125`, `B < 120`. |
| Мощение (`pave`) | `128, 128, 128` | `#808080` | Каналы близки друг к другу (разница меньше 22), яркость выше 90. |
| Вода (`water`) | `0, 0, 255` | `#0000FF` | Синий превышает красный больше чем на 35 и зелёный больше чем на 20. |
| Старт игрока | `255, 0, 0` | `#FF0000` | Маркер `spawn`. |
| Руда | `255, 128, 0` | `#FF8000` | Маркер `ore`. |
| Самоцветы | `255, 0, 255` | `#FF00FF` | Маркер `gems`. |
| Локация/точка интереса | `0, 255, 255` | `#00FFFF` | Маркер `location`. |

Маркеры проверяются раньше классов местности и допускают погрешность `markerTolerance` от 0 до 64 (по умолчанию 12). Точные цвета из таблицы всегда безопаснее. Красные spawn-маркеры превращаются в waypoint `0..7` (не более восьми, с защитой от слишком близких точек), cyan location — в waypoint начиная со `100`, orange/magenta — в клетки руды/самоцветов.

Высоту можно получить из той же картинки: `heightMode: "none"` оставляет `startingHeight`, `"luminance"` использует яркость пикселя, а `"red"` — красный канал. Полученная добавка масштабируется от 0 до `maxHeight`, суммируется со `startingHeight` и ограничивается диапазоном FinalAlert `0..14`. Цвет одновременно участвует и в классификации местности, поэтому для строгого контроля часто проще импортировать с `heightMode: "none"`, а высоты задать после импорта через `finalalert.paint_region`/`finalalert.set_cells`. `autoShore` строит берега воды, `autoSmooth` применяет сглаживание театра.

Актуальные параметры и значения по умолчанию всегда берите из `inputSchema`, полученной через `tools/list`.

Практический AI-процесс:

1. Сгенерировать композиционный эскиз, затем преобразовать его в semantic mask из цветов таблицы.
2. Создать карту непосредственно через `finalalert.import_semantic_image`, передав `width`, `height`, `theater` и `targetGame: "ra2"` или `"yr"`. Для карты без картинки вместо этого используйте `finalalert.create_map`.
3. Проверить получившиеся клетки и найденные маркеры.
4. Уточнить высоты и проходимость через `finalalert.get_cells`, `finalalert.set_cells` и `finalalert.paint_region`.
5. Расставить спауны, ресурсы, waypoint и объекты, сверяясь с `finalalert.list_catalog`.
6. Вызвать `finalalert.validate_map`, получить `finalalert.get_preview`, визуально проверить баланс и симметрию.
7. Сохранить сначала в новый `.map`, `.mpr` или `.yrm` через `finalalert.save_map`.

Для Red Alert 2 не используйте YR-only театры `NEWURBAN`, `LUNAR` и `DESERT`. Реальные имена зданий, юнитов, декораций и тайлов зависят от загруженных INI/мода, поэтому модель должна сначала запросить `finalalert.list_catalog`, а не угадывать type ID.

## Каталог tools

Точный контракт аргументов и аннотации (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) публикуются самим сервером через `tools/list`. Ниже перечислены все ожидаемые инструменты текущего билда.

| Tool | Тип | Назначение |
| --- | --- | --- |
| `finalalert.get_status` | чтение | Состояние редактора, MCP и загруженной карты. |
| `finalalert.get_map_info` | чтение | Размеры, театр, режим и основные метаданные карты. |
| `finalalert.get_cells` | чтение | Тайлы, высоты и состояние выбранных клеток/области. |
| `finalalert.list_catalog` | чтение | Доступные типы объектов/домов, точные tile ID и overlay/resource ID из активного театра и INI. |
| `finalalert.list_objects` | чтение | Размещённые на карте объекты с координатами и свойствами. |
| `finalalert.get_preview` | чтение | Актуальное BMP-превью карты и, по запросу, base64-данные. |
| `finalalert.validate_map` | чтение | Проверка структуры карты, спаунов и типичных ошибок. |
| `finalalert.get_ini_section` | чтение | Чтение указанной секции INI карты. |
| `finalalert.create_map` | изменение | Создание новой карты заданного размера, театра, высоты и target game. |
| `finalalert.import_semantic_image` | изменение | Преобразование semantic image в рельеф, ресурсы и маркеры карты. |
| `finalalert.open_map` | изменение | Неинтерактивное открытие существующего `.map`, `.mpr` или `.yrm`. |
| `finalalert.save_map` | изменение | Атомарное сохранение карты по указанному абсолютному пути. |
| `finalalert.set_map_metadata` | изменение | Название, автор, описание, режим и другие метаданные. |
| `finalalert.set_cells` | изменение | Точные пакетные изменения отдельных клеток и высот. |
| `finalalert.paint_region` | изменение | Закраска области типом местности/высотой. |
| `finalalert.place_resources` | изменение | Расстановка руды или самоцветов с заданными ограничениями. |
| `finalalert.place_waypoint` | изменение | Установка или перенос waypoint. |
| `finalalert.set_player_spawns` | изменение | Настройка стартовых точек игроков. |
| `finalalert.place_object` | изменение | Размещение здания, юнита, пехоты, декорации или другого объекта каталога. |
| `finalalert.delete_at` | изменение | Удаление подходящих объектов в указанной позиции. |
| `finalalert.set_ini_value` | изменение | Низкоуровневая запись ключа в секцию INI карты. |
| `finalalert.apply_map_plan` | изменение | Последовательное применение плана с checkpoint rollback для существующей карты. |
| `finalalert.undo_terrain` | изменение | Отмена snapshot рельефа/высоты/overlay; объекты и INI не входят. |
| `finalalert.redo_terrain` | изменение | Повтор snapshot рельефа/высоты/overlay; объекты и INI не входят. |

Первые восемь инструментов являются read-only. Все остальные требуют уникальный `operationId` в `arguments`.

## Диагностика

- `/health` недоступен: редактор не запущен, сервер отключён, порт занят или запрос не содержит настроенный Bearer token.
- `401`: неверный/отсутствующий `Authorization: Bearer ...`.
- `403`: не прошла проверка `Host` или `Origin`.
- `405` на `GET /mcp`: ожидаемое поведение современного endpoint; используйте `POST`.
- `Header mismatch` в MCP 2026-07-28: заголовки `Mcp-Method`/`Mcp-Name` не совпадают с JSON body либо версия отсутствует в `params._meta`.
- `editor_busy`: закройте диалог редактора и повторите ту же операцию с тем же `operationId`.
- неизвестный объект/тайл: обновите каталог через `finalalert.list_catalog` для активной игры и мода.

Протокольная справка: [MCP 2026-07-28 Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) и [MCP 2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
